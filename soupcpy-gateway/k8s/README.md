# Deploying the gateway on Kubernetes

Kustomize base plus two overlays, for ingress-nginx.

```bash
kubectl apply -k k8s/overlays/dev     # local cluster, http on localhost
kubectl apply -k k8s/overlays/prod    # TLS ingress, pinned image tag
kubectl kustomize k8s/overlays/prod   # render without applying
```

## Read this before you deploy

### The gateway runs exactly one replica

All routing state lives in process memory: `ConnectionRegistry` holds the live
sockets and `ChannelStore` holds the channel snapshots that controllers push.
Receivers and controllers are paired by `udid` *within a single process*.

With two replicas, a receiver can land on one pod while its controller sits on
another. Nothing errors -- the stream just never starts, and `/api/channels`
returns different answers depending on which pod answers. So:

- `replicas: 1`, and no HorizontalPodAutoscaler.
- `strategy: Recreate`, because a RollingUpdate briefly runs two pods and
  splits the registry during the overlap.

Scaling out is a code change, not a manifest change. It needs the registry and
channel store moved behind something shared (Redis pub/sub, or routing all
sockets for one udid to one pod), and the log broadcast moved off the
in-process `tokio::sync::broadcast`.

The flip side: a pod restart drops every stream and empties the channel list
until the controllers re-push their snapshots. There is no persistence here.

### Agents do not run in the cluster

The agent needs `adb` and USB access to physical phones, so it runs on the
machines the devices are plugged into and dials *in* to the gateway. Only the
gateway is deployed here. Point each agent's `controller_endpoint` at the
ingress host, with `wss://` when TLS is terminated:

```yaml
# soupcpy-agent/config/config.yml
controller_endpoint: "wss://gateway.example.com/ws/controller"
publisher_endpoint: "wss://gateway.example.com/ws/publisher"
```

### The agent endpoints are unauthenticated

`/ws/controller` and `/ws/publisher` have no authentication. Anything that can
reach them may register as the controller for any `udid` and take over routing
for that device.

The prod overlay therefore splits them into a second Ingress
(`ingress-agents.yaml`) carrying `whitelist-source-range`, so they can be
restricted to the addresses your agents dial from. **That CIDR is a required
edit** -- the placeholder `203.0.113.0/24` is a documentation range and will
match nothing real. nginx-ingress matches the longest path prefix, so those two
rules win over the `/` rule in the main Ingress.

A source-range allowlist is a mitigation, not authentication. A shared token on
those endpoints is the real fix and does not exist yet.

## Configuration

Everything comes from `GATEWAY_*` environment variables, supplied by the
generated ConfigMap. The same variables drive `docker-compose.yml`, so one
image serves both.

| Variable | Purpose |
| --- | --- |
| `GATEWAY_HOST` | Bind address. `0.0.0.0` in a container; `127.0.0.1` is unreachable from outside the pod. |
| `GATEWAY_PORT` | Bind port, matching `containerPort`. |
| `GATEWAY_PUBLIC_HOST` | Host a browser uses. Only affects the links the dashboard builds. Leave it unset and the gateway advertises nothing, so each dashboard falls back to the origin it was loaded from -- fine for a bare `docker run`, but set it explicitly here. |
| `GATEWAY_PUBLIC_PORT` | Port a browser uses. Omitted from links when it matches the scheme's default (80/443). |
| `GATEWAY_PUBLIC_SCHEME` | `http` or `https`. **Set `https` behind a TLS ingress** -- this is what makes the dashboard emit `wss://`. On an `https` page a `ws://` URL is blocked as mixed content, so the streams silently fail to open. |
| `RUST_LOG` | Tracing filter, e.g. `info,rust=debug`. |

A malformed value fails startup rather than being ignored, so a typo shows up
as a crash-looping pod instead of a gateway quietly advertising wrong links.

The ConfigMap is generated by `configMapGenerator`, so its name carries a
content hash and editing a value actually restarts the pod on re-apply.

`GATEWAY_CONFIG` still points at a TOML file if you prefer that route;
environment variables are layered on top and win.

## What is not covered

- **No NetworkPolicy.** Add one if the cluster is shared.
- **No PodDisruptionBudget.** With one replica a PDB cannot help; node drains
  will drop streams.
- **No metrics.** The app exposes `/health` only, so there is nothing for a
  ServiceMonitor to scrape.
- **Probes share `/health`,** which reports process liveness, not whether
  device routing works. A gateway with every agent disconnected still reads
  healthy.
